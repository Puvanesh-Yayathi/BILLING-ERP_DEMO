# 12. Build plan and prompts

Build in this order. Finish and verify each phase before starting the next. Commit after each phase. Follow `CLAUDE.md`.

## Using Claude Code inside Antigravity
- Put this whole folder in the project root (`CLAUDE.md` at the root, `docs/` beside it). Open the folder in Antigravity and start Claude Code there.
- Give Claude Code **one phase at a time** using the prompts below. Do not ask for the whole project at once.
- After each phase: run `pnpm test`, run the app with `pnpm dev`, click through the screens, compare with doc 08, then commit.
- Optional parallel work in Antigravity (only **after Phase 1**, once the contract and design system exist): one agent on back-end services and tests, another on front-end screens, a third on print templates. Agree on the contract in `/packages/contract` first so they do not collide. Never let two agents edit the same file.

## Master prompt (paste first, once)
> Read `CLAUDE.md` and every file under `docs/` completely before writing any code. You are building the Demo Edition described there: a React frontend and a Hono backend on Netlify Functions, with bundled generic seed data and no external database. Work phase by phase from `docs/12-build-plan-and-prompts.md`. Do not start a phase until I ask. For each phase: write tests first for calculators and services, implement, run the tests and the app, check the UI against `docs/08-ui-design-system.md`, update `DECISIONS.md`, and commit. Do not invent features. If something is ambiguous, follow the assumptions in `docs/01-overview-and-scope.md`, choose the simplest sensible option and log it. Confirm you have read everything by summarising the architecture in ten lines.

## Phase 0: Foundation
> **Phase 0.** Create the pnpm workspace (`apps/web`, `netlify/functions`, `server`, `packages/contract`), strict TypeScript, ESLint (web may import only the API client), Prettier, Vitest, Playwright, `netlify.toml` (SPA fallback, security headers, caching, function config with the `rateLimit` rule), and GitHub Actions CI. Implement the Hono API function with middleware (request id, auth with JWT cookie, app-level rate limiter, zod validation, idempotency, error mapping), the `DataStore` interface with `MemoryStore` and `BlobStore` (compare-and-set transactions, retries), the event log and `GET /events`, the audit log, the request-log ring buffer, `GET /healthz`, and the scheduled sweeper. Implement the generic seed loader skeleton and `pnpm verify:seed`. Build the design tokens, IBM Plex Sans (self-hosted), base components, motion system, app shell (sidebar, top bar, role navigation), and **the login page exactly as specified in doc 08** (contour graphic, one-time entrance, lockout countdown, brand from the company profile). Done when: login works for all seeded roles, wrong password and lockout behave per RATE-1, tests pass, build passes, and the login page matches the spec on desktop and phone widths.

## Phase 1: Masters, users, company profile
> **Phase 1.** Implement Modules 1, 2 and 12 from doc 03: Workers and Logins (create worker with login ID and password, cap `maxWorkerLogins`, Admin-only reset), other users, audit log screen, login history, company profile with versioning and live branding everywhere, calendar, all masters (Purchase List, Sales Inventory, suppliers, customers, distributors, expense heads, bank accounts, units, categories), Excel import with preview and validation, and the customer and distributor profile pages. Follow the API table in doc 07. Done when the demo steps for setup and branding (doc 11, steps 17 and 18) pass, branding changes appear on the login page and header immediately, and the 11th worker login is refused by the server.

## Phase 2: Billing, payments, print engine
> **Phase 2.** First implement and unit-test `calcInvoice` against vectors I-1 to I-3, document numbering NUM-1, payment allocation PAY-1 and stock reservation STK-1 in `packages/contract` and `server/services`. Then build Modules 3 and 4: billing screen (products only from the Sales Inventory with live stock), draft and finalize, cancel, payments and receipts, dues and overdue. Build the **print engine and the A4 invoice template exactly per doc 09** (10 mm margins, 190 mm column grid, repeating header and table heading, totals on the last page only, at least two item rows on the last page, UPI QR) and receipt template. Add the Playwright print tests for 1, 10, 12, 25 and 60 items. Done when a 12-item invoice prints with the header and table heading repeated on page 2, all vectors pass, and no content crosses the margins.

## Phase 3: Funds, purchasing, approvals
> **Phase 3.** Build Modules 5 and 6: fund tracker with loans, purchase indent (items from the Purchase List, editable rates, fund warning FUND-1), the 3-stage approval state machine (IND-1), approvals inbox per role, notifications and the simulated outbox, PO print template, purchase bill and goods receipt (Admin or Operating, supplier bill number, rate variance), supplier payment and fund utilisation. Done when demo steps 2 to 7 pass and the role restrictions return 403 as specified.

## Phase 4: Inventory and production
> **Phase 4.** Build Module 7: Purchase List and Sales Inventory views, production batches (atomic), the inventory tracker with both tabs, item movement timelines, low-stock alerts, stock take with variance adjustments, and manual adjustments. Done when demo steps 8 and 22a pass, Product G cannot be billed, Product H shows the low-stock alert, and `pnpm verify:seed` invariants 1 and 2 hold.

## Phase 5: Ledgers, attendance, payroll, settlement
> **Phase 5.** First implement and unit-test `calcPayslip` (vectors P-1 to P-5, hours rounding, W-1, W-2, S-1) and `calcSettlement` (ST-1 to ST-4). Then build Modules 8 and 9 and 11: ledgers and day book, automatic attendance from login, logout, heartbeat and idle timeout (scheduled sweeper), attendance grid with Admin corrections, advances, payroll overview and payslip (preview, draft, pay, cancel, bulk), worker My Pay, Other Expenses, and the profit settlement with individual and consolidated payslips. Done when demo steps 14 to 14f pass, a worker can never see profit, loan or another worker's pay, and the consolidated payslip matches doc 03.

## Phase 6: Analytics, explorer, reports, distributor
> **Phase 6.** Build Module 10: analytics dashboards for Admin (Daily, Weekly, Monthly, Yearly with comparison and drill-down), the live activity feed using event polling, the worker dashboard (own data only), Monitor and Collector views without profit, the Bills Explorer (overall and worker-wise), the 12 reports with Excel export and print, the distributor portal and order requests. Follow doc 08 for layout, chart style and motion (count-up and chart draw once on first load). Done when demo steps 12, 13, 15, 16, 19 and 21 pass and a bill made on one device appears on the Admin screen within about 2 seconds.

## Phase 7: Hardening and polish
> **Phase 7.** Build Admin → System (request log with function instance ids, API Explorer from the generated OpenAPI, the labelled production architecture diagram), `pnpm loadtest` (concurrent workers, shows 429s and several instance ids), idempotency and conflict demos, Lighthouse and bundle budgets, the full Playwright run of the demo script (doc 11), accessibility checks, reduced-motion check, and the **design acceptance checklist in doc 08**. Fix everything found. Write `README.md` (local run, deploy to Netlify, environment variables, demo logins, reset, demo script, what is real versus simulated). Done when all 23 demo steps pass on a Netlify deploy preview and every item in the definition of done in `CLAUDE.md` is met.

## Deploy
Connect the repository to Netlify. Set `JWT_SECRET` (long random value), `DATA_STORE=blobs`, `DEMO_RESET_ENABLED=true`. Check the deploy log shows the rate-limit rule. Open the site, sign in as `admin`, and run the demo script. Use a deploy preview for rehearsals.

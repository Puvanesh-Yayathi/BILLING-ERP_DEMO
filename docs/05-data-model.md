# 05. Data model

## 4. Data Model

These entities are collections inside the **transactional state document of the Demo Edition** (Section 2B) and the **Prisma/Postgres tables in production**: same names, same fields, same rules. Types below use database terms; in the demo store money as integer paise and quantities as numbers with 3 decimals.

Use integer paise (or `Decimal`) for all money. **Never use floats for money.** Quantities are `Decimal(12,3)`.

**Auth/system:** `User(id, username, passwordHash, name, role, customerId?, active)`, `ActivityLog(id, userId, entity, entityId, action, before?, after?, at)`, `Setting(key, value)`, `Notification(id, userId, title, body, link, read, at)`, `EmailOutbox(id, to, subject, body, at)`, `Counter(key, value)` for numbering.

**Masters:** `Customer(id, code, name, type[RETAIL|DISTRIBUTOR], phone, address, gstin?, state, openingBalance)`, `Supplier(id, name, phone, address, gstin?, openingBalance)`, `Unit(id, name)`, `ProductCategory(id, name)`, `Product(id, code UNIQUE, name, categoryId, unitId, hsn?, gstRate, taxInclusive, mrp, retailPrice, distributorPrice, reorderLevel, active)` (this is the Sales Inventory), `RawMaterial(id, name, category[RAW_MATERIAL|PACKAGING|CONSUMABLE|OTHER], unitId, preferredSupplierId?, lastRate?, reorderLevel, active)` (this is the Purchase List), `Staff(id, name, phone, userId? (links to a login), payType[FIXED|HOURLY|SHARE], basePay? (FIXED), hourlyRate? (HOURLY), sharePercent? (SHARE), reduceByAbsence bool default false (SHARE), joinDate, active)`, `CompanyHoliday(id, date, name)`, `ExpenseHead(id, name)`, `BankAccount(id, bankName, accountName, accountNo, ifsc, upiId, isInvoiceDefault)`.

**Sales:** `Invoice(id, number, date, type[CASH|CREDIT|DISTRIBUTOR], customerId, status[DRAFT|SENT|PAID|OVERDUE], dueDate?, subtotal, discountTotal, taxableTotal, cgst, sgst, igst, roundOff, grandTotal, paidAmount, createdById)`, `InvoiceItem(id, invoiceId, productId, qty, rate, discountPct, taxableValue, gstRate, cgst, sgst, igst, lineTotal)`, `Payment(id, receiptNo, date, customerId, invoiceId?, mode[CASH|UPI|BANK|CARD], amount, reference?)`, `OrderRequest(id, distributorId, items JSON, note, status[NEW|CONVERTED|REJECTED], invoiceId?)`.

**Funds and purchase:** `FundTranche(id, date, source, amount, note, isLoan, lender?)`, `LoanRepayment(id, trancheId, settlementId?, date, amount, mode, note)`, `ProfitSettlement(id, month, status[DRAFT|FINALIZED|CANCELLED], sales, purchases, grossProfit, loanRepayment, poolAfterLoan, fixedHourlyTotal, shareTotal, scaleFactor, otherExpenses, ownerAmount, shareBase, finalizedAt?, createdById)`, `SettlementLine(id, settlementId, staffId, payType, earned, sharePercent?, computed, adjustment, adjustmentReason?, payable, alreadyPaid, balancePayable, payslipId?)`, `PurchaseIndent(id, number, date, supplierId, status[DRAFT|PENDING_S1|PENDING_S2|PENDING_S3|APPROVED|REJECTED|RECEIVED|PAID], total, raisedById)`, `IndentItem(id, indentId, rawMaterialId, qty, rate, amount)`, `IndentApproval(id, indentId, stage[1|2|3], decision[APPROVED|REJECTED], remarks, userId, at)`, `GoodsReceipt(id, indentId, date, items JSON of received qty, supplierBillNo?, supplierBillDate?, billAmount, note)`, `SupplierPayment(id, indentId, date, mode, amount, reference?)`.

**Stock/production:** `RawStockMovement(id, rawMaterialId, qty ±, reason[PURCHASE|PRODUCTION|ADJUSTMENT], refType, refId, date, note)`, `ProductionBatch(id, batchNo, date, createdById, wastageQty, wastageNote)`, `ProductionInput(batchId, rawMaterialId, qty)`, `ProductionOutput(batchId, productId, qty)`, `StockCount(id, date, kind[PURCHASE|SALES], status[DRAFT|CONFIRMED], createdById)` with `StockCountLine(countId, itemId, systemQty, countedQty, variance, reason?)`, `FinishedStockMovement(id, productId, qty ±, reason[PRODUCTION|SALE|CANCEL|ADJUSTMENT], refType, refId, date, note)`.

**Staff/expenses:** `Attendance(id, staffId, date, status[PRESENT|ABSENT|HALF|LEAVE], firstIn?, lastOut?, rawMinutes, paidHours (rounded), source[AUTO|MANUAL|EDITED], payslipId?)` with UNIQUE(staffId, date), `AttendanceSession(id, staffId, date, loginAt, lastSeenAt, logoutAt?, endReason[LOGOUT|IDLE_TIMEOUT|AUTO_CLOSE|MANUAL])`, `StaffAdvance(id, staffId, date, amount, recoveredAmount)`, `Payslip(id, number, staffId, periodFrom, periodTo (inside one calendar month), status[DRAFT|PAID|CANCELLED], payType, rateSnapshot JSON, workingDaysInMonth?, perDayRate?, daysPresent, halfDays, absentDays, paidHours, basePayEarned, allowancesTotal, deductionsTotal, advanceRecovery, gross, net, paidOn?, mode?, reference?, cancelReason?, createdById)`, `PayslipLine(id, payslipId, kind[ALLOWANCE|DEDUCTION], label, amount)`, `Expense(id, date, headId, amount, description (required), createdById)` (the "Other Expenses" section).

**Branding and logs:** `CompanyProfile(id, versionNo, effectiveFrom, brandName default "[Your Brand Name]", legalName?, addressLine1, addressLine2?, city, state, stateCode, pincode, phone, email, website?, gstin?, logoAssetId?, faviconAssetId?, invoiceTerms, footerNote, signatoryLabel, createdById)` where **each edit creates a new version row** and never changes old ones. `Asset(id, kind, mime, path, sha256, width, height, createdAt)` (old assets are never deleted). `LoginEvent(id, userId?, username, outcome[SUCCESS|FAILED|LOCKED|LOGOUT|TIMEOUT], ip, userAgent, at)`. `ActivityLog` gains `ip`, `requestId`, `summary`, and is **append-only** (no update or delete in the API or DB role).
**Every printable record** (Invoice, Payment/receipt, PurchaseIndent/PO, GoodsReceipt, SupplierPayment, Payslip, ProfitSettlement) stores `companyProfileVersionId` at the moment it is **finalized**, so old documents always reprint with the company details they were created with. Drafts use the live profile until finalized. `IdempotencyKey(key, route, userId, responseHash, at)`.

**Stock is always derived** by summing movement tables. Never store a mutable "current stock" number. Every movement row is created inside the same DB transaction as the business event that caused it.
